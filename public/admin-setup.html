ONE-TIME SETUP

Connect your catalog.

R2 stores product photos, D1 stores product details, and a Cloudflare Worker safely handles admin access and uploads. GitHub Pages continues to host the customer storefront.

1. Prepare a Cloudflare account

Sign in at dash.cloudflare.com ↗. R2 requires enabling the R2 subscription through Cloudflare’s checkout flow. It has monthly free usage allowances; usage beyond those allowances is billed.

2. Create the D1 database and R2 bucket

On your computer, clone the website repository ↗ and open its worker/ folder. Install Wrangler and log in, then create the resources:

npm install
npx wrangler login
npx wrangler r2 bucket create aa-digital-world-product-images
npx wrangler d1 create aa-digital-world-catalog

Copy the D1 database_id Wrangler returns into worker/wrangler.toml where it says REPLACE_WITH_D1_DATABASE_ID. Set ADMIN_EMAIL to the shop owner's login email. The default Pages origin is already configured. If your Pages URL differs, set ALLOWED_ORIGIN to its origin (scheme and hostname only).

3. Set up the catalog database

From the worker/ folder, apply the schema and starter catalog to the remote database:

npx wrangler d1 migrations apply aa-digital-world-catalog --remote

4. Set private admin credentials and deploy

Choose a unique password at least 16 characters long. Wrangler prompts for each value; don’t add these secrets to the repository:

npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET

Use a random value of at least 32 characters for SESSION_SECRET. Deploy the API:

npx wrangler deploy

5. Connect GitHub Pages to the API

Wrangler prints the Worker URL (ending in .workers.dev). In public/admin-config.js, set apiBaseUrl to that URL, commit the change to master, and wait for GitHub Pages to finish deploying.

6. Add products

Open the admin page ↗ and sign in with the configured email and password. Upload a JPG, PNG or WebP photo up to 5 MB, then add the product details. Published products appear on the storefront right away.

If you later change the Worker API URL or public Pages origin, update public/admin-config.js or worker/wrangler.toml respectively, then deploy the Worker and push the Pages change.

Keep secrets private.

Admin password and session secret belong in Wrangler secrets only. The Worker never exposes them to GitHub Pages or the browser.
